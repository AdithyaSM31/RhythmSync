# Per-device EQ Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give every client PC and the host's own speakers a 10-band graphic EQ, set on the host and applied on each PC's audio thread, so different speakers can be matched by ear.

**Architecture:** Pure Core types (`EqGains`, `EqCurve`, `EqPresets`) are shared by both sides. A lock-free `EqProcessor` runs first in each `ClientPipeline`'s `DspChain`. The gains travel in `SetDeviceSettings` (protocol v2) and persist in `DeviceSettings`. On the host, `ClientRowViewModel` and a new `LocalSpeakerRowViewModel` each own an `EqViewModel`, rendered with the merged "Dark studio" design system.

**Tech Stack:** C# / .NET 10, WPF, xUnit, CommunityToolkit.Mvvm, System.Text.Json.

**Spec:** `docs/superpowers/specs/2026-10-18-eq-design.md` (read it with this plan; § numbers below refer to it). UI tokens and components: `docs/superpowers/specs/2026-10-18-ui-redesign-design.md`.

## Global Constraints

- Bands: centres `1000 · 2^(k−5)` Hz for k = 0…9 (31.25 … 16000), labels `31 63 125 250 500 1k 2k 4k 8k 16k`, Q = 1.41, ±12 dB, 0.5 dB steps.
- A band whose centre is ≥ 0.45 × sample rate is treated as 0 dB.
- Smoothing: sub-blocks of 32 frames, one-pole τ = 10 ms, snap to target within 0.01 dB. Filter state in `double`, TDF-II. Denormal flush: |s| < 1e-30 → 0 at the end of each `Process` call.
- `EqProcessor.Process` must not allocate, lock or block. Only the control side (`SetGains`, `SetSampleRate`) may allocate or lock.
- Flat is bit-exact: `Process` returns without touching samples when every current and target gain is 0 and the preamp is 1.
- Preamp = −max(0, peak of the curve), evaluated over 601 log-spaced points from 20 Hz to min(20 kHz, 0.45·rate) plus every active band centre.
- The wire format and the settings file carry `float[]? EqGainsDb`. Null or missing means Flat. Never add a strict JSON converter, because `ControlCodec` drops the connection on a `JsonException` and `SettingsStore` moves the file to `.bak`.
- `HostSession.ProtocolVersion` = 2.
- The host is the single source of truth (R15). The Join page shows the EQ read-only and has no EQ controls.
- Copy (exact): presets `Flat`, `Laptop speakers`, `Bass boost`, `Treble cut`, plus `Custom`; `This PC`; `Playing here`; `Not playing on this PC`; `EQ`; `Preset`; `Flat` (button); `Preamp {x:0.0} dB`; Join page `EQ: {name}`.
- UI uses only the merged resource keys: `CardBorder`, `SubtitleText`, `CaptionText`, `StatText`, `GhostButton`, `StudioFocusVisual`, `TrackBrush`, `AccentGradientBrush`, `CardBorderBrush`, `TextBrush`, `TextMutedBrush`, `FontIcons`.
- Commit messages carry no attribution or `Co-Authored-By` lines.
- Default test suite: `dotnet test --filter "Category!=Hardware&Category!=Smoke"`. It must pass after every task, and the build must have 0 warnings.

## Review Focus

1. **A volume or offset change after an EQ change** (in the client Card or the tray flyout's volume slider) must send the row's current EQ, never Flat. Test: Task 8, `Volume_change_after_an_eq_change_resends_the_same_eq`.
2. **`SetGains` racing `SetSampleRate`.** On the client, the control reader thread and the output-rebuild path can call them at the same moment. The final target must be computed for the final rate. Test: Task 3, `Concurrent_SetGains_and_SetSampleRate_end_with_a_preamp_for_the_final_rate`.
3. **Low device rates** (a Bluetooth hands-free profile at 16 kHz, or 22.05 kHz): no NaN, no instability, bands above 0.45·rate ignored, and `PeakDb` finite. Test: Task 3, `A_16kHz_device_ignores_the_top_bands_and_stays_finite`.
4. **Buffer sizes** that are not multiples of 32, including 1 frame and an empty span. In steady state, the output must be identical however the input is split. Test: Task 3, `Steady_state_output_does_not_depend_on_how_buffers_are_split`.
5. **The host's own EQ after a restart.** It must be applied when local playback starts, which can happen before any view model exists. Test: Task 7, `StartLocal_applies_the_stored_local_eq_before_any_view_model_change`.

  - Review Focus 2, `Concurrent_SetGains_and_SetSampleRate_end_with_a_preamp_for_the_final_rate`: two threads, 1 000 calls each (gains: random presets; rates: 44100/48000). Afterwards `CurrentTarget.SampleRate == SampleRate` and `CurrentTarget.PreampLinear == 10^(PreampDb(Gains, SampleRate)/20)`.

  - Review Focus 4, `Steady_state_output_does_not_depend_on_how_buffers_are_split`: settled +6 on 3 bands. The same 4 800 frames processed as one call, or as calls of 1, 31, 33 and 1 023 frames → identical output. An empty span is a no-op.
